# Personal Agent

> 本地优先、记忆可审计、能真正调用工具办事的通用个人 Agent。

**状态：早期原型 + 公开设计阶段。**

这不是成品，也不是功能清单。当前仓库同时包含：

- 已经能运行的原型；
- 正在验证的架构；
- 还没有实现的设想。

我们会明确区分这三类内容，不把设计写成已完成。

---

## 为什么做这个

现有 Agent 不只是“记忆不够好”，而是在六个地方断开：

1. **记忆上断**  
   要么是聊天摘要，时间一长就失真；要么是不断膨胀的 Markdown 文件堆，过期、矛盾和重复无人处理。两种都回不到原话。

2. **场景上断**  
   学习、编程、工作、生活被拆成不同 App、不同模式、不同人格，甚至不同记忆。

3. **证据上断**  
   Agent 说做完了，实际可能只生成了一个页面、一段文案，没有真实文件、测试或运行结果。

4. **归属上断**  
   数据、记忆和对话历史留在平台手里；换模型、换服务商，过去就带不走。

5. **身份上断**  
   文件和文件夹成了事实上的身份；一改名、一移动，历史引用和关联就断。

6. **表达上断**  
   中文任务被迫绕英文推理，工具名和提示词把思考方式也一起绑住。

再往远一点，我们想要的不只是效率工具：

> 一个能陪一个人很多年、真的理解他的经历、关系和判断的 Agent，而不是每次都从零开始的聊天框。

Personal Agent 想解决的是这些断点，而不是再做一个聊天界面。

---

## 它是什么

> **一个通用个人 Agent 内核 + 你自己定义的场景。**

通用内核负责：任务、工具、资源、产物、版本、记忆、权限。

场景是你为某类事情定义的一套组合：用哪些能力、看哪些资源、界面怎么排、记忆怎么用、什么时候主动提醒。

**学习只是其中一个示例场景，不是产品本身。**  
任何人都可以直接使用通用场景，也可以为自己定义场景；场景之间共享同一套任务、资源和记忆。

### 不只是聊天：三种产物

| 产物 | 例子 | 为什么 |
|---|---|---|
| 交互组件 | 答题卡、表单、图表、对比卡 | 直接在对话里操作，不用来回描述 |
| 文档 / 幻灯片 / 表格 | Word、PPT、Excel、PDF | 落成真实文件，能打开、能改、能导出 |
| 查看器 | 文档、表格、幻灯片、图片、diff | 让你亲眼看到“做完了”是什么样，并记住看到哪里 |

### 五个差异点

| 差异 | 含义 |
|---|---|
| 场景可自定义 | 不把学习、编程、写作写死成产品模式；用户自己组合，也可以分享和安装场景 |
| 记忆跨场景连续 | 换场景不换人格、不丢背景；人物、项目、目标和决定仍然连在一起 |
| 资源与路径分离 | 文件夹只是位置，不是身份；移动、重命名、多项目共用不会断 |
| 证据式完成 | 编程看测试与 diff，文档看真实产物，学习看用户能否独立完成 |
| 产物不是网页 | 需要交互时输出组件，需要文件时输出 DOCX/PPTX/XLSX；都能打开检查 |

## 架构一览

```text
对话 / 编辑器 / wiki / 日程 / 消息
                │
                ▼
        统一任务与执行内核
  目标 · 计划 · 行动 · 审批 · 停止 · 恢复 · 验证
                │
     ┌──────────┼──────────┐
     ▼          ▼          ▼
  场景组合   资源与产物   自动化运行
                │
                ▼
        上下文与长期记忆内核
  原始经历 / 证据 / wiki / 按需回忆
                │
                ▼
   本地 SQLite · 文件 · Codex · 模型 · 渠道
```

核心不是“功能多”，而是这些部分共享同一套任务、资源、版本和记忆。

## 设计不变量

这些是项目不能破坏的约束：

1. 原始事件与派生理解分开。
2. 资源身份不等于文件路径。
3. 对话、代码、文档可以分别恢复，也可以一起恢复。
4. 记忆必须有证据，模型不能凭空写入事实。
5. 当前理解变化，不篡改历史。
6. 偏好和人格是带反证的假设，不是永久标签。
7. 遗忘要级联处理派生内容，不能只隐藏。
8. 主动行为先看本地条件，再决定是否调用模型。
9. 没有真实产物或验证结果，不得声称完成。
10. 场景不能创建独立记忆库，也不能静默扩大权限。
11. 本地优先，模型可替换，数据可导出。

## 如何参与

现阶段最有价值的贡献不是堆功能，而是：

- **挑战设计**：指出哪个假设站不住；
- **带一个场景**：说明你想用它做什么、现在哪里不行；
- **带一个反例**：给出可复现的失败；
- **带一个补丁**：小而完整，附验证证据；
- **带一组评测**：证明记忆是否可靠；
- **带一个界面或文档样例**：说明 Intelligent UI、Office AI 或查看器应该长什么样。
