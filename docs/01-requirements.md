## 0. 基线状态

### 0.1 已确认

- 产品身份是 **Personal Agent**，不是 Learning AI；学习是第一个深垂直场景。
- **一个对话/工作台**：Chat、Work、Codex、Learning 不分成 tab，不切换模式。
- **Rust 后端，禁止 Electron**；本地优先，性能接近 CLI。
- **DeepSeek Flash 默认**；模型可替换；Pro 可选，不进默认路径。
- **200 元/月**；10 个场景 × 平均 500 轮/月。
- **学习优先**：9 科 + 体育；2027 年中考。
- **记忆原则**：Scene/原话是真相；Portrait/人物志是散文；Index 只是索引；不把人做成一坨 JSON。
- **记忆可检查、可编辑、可遗忘、可导出**。
- **记忆核心体验对标 ChatGPT Dreaming V3**：后台跨对话合成、时间改写、用户可见/可编辑；不是 Codex 式 Markdown 任务记忆。
- **开源、免费商用、Apache-2.0**；要 Star、名字、影响力。
- **不做跨工具记忆共享**。
- **3–4 天全职**做出 50–70% 的可测原型。

### 0.2 待评审

- 组织单位：对话/场景为基本单位，项目/主题/人物/决策是关系与视图，不是文件夹。
- 第一版演示场景：学习 + 项目/决策 + 上下文续接。
- StudyOS：产品内置取代，并兼容导入其 JSON。
- 第一个非聊天界面：概念图 / 错题本 / 学习画布，三选一。
- 遇到根本性困惑时：停下来重建直觉，而不是继续按教材推进。

## 1. 背景与机会

### 1.1 市场窗口

- ChatGPT Plus 近期出现质量、额度、降智争议；2026 年 12 月起 ChatGPT 与 Codex 共用 token 额度（Instant chat 除外）。
- 用户当初为“20 美元无限对话 + 能真实干活”而来；额度政策变化后，成本敏感用户会寻找替代。
- 国内模型网页普遍不能“不计额度地做 PPT/跑代码/长搜索”；DeepSeek 按量计费，成本可控。
- 开源 Agent 很多，但终端用户可用的、可审计的长期记忆产品缺位。

### 1.2 机会

- 用 DeepSeek + 本地沙箱 + 可审计记忆，做一个 ChatGPT Plus 的开源替代。
- 用真实学习/项目对话证明“一个对话、一套记忆、不切模式”的体验。
- GitHub 开源 + 小红书传播，争取 1K–2K Star 与共创者。

## 2. 产品定义

### 2.1 一句话

> 一个本地优先、记忆可审计、会跨对话“做梦”（Dreaming）的个人 Agent。

### 2.2 不是什么

- 不是 Learning AI 或课程 App。
- 不是 ChatGPT 的套壳。
- 不是插件市场或 Agent 框架。
- 不是企业多租户/团队协作产品。
- 不是“把所有历史塞进 1M 上下文”的聊天工具。

### 2.3 三个支柱

1. **对话**：一个对话里完成学习、工作、编程、决策，不切模式、不新开对话。
2. **记忆**：Scene → Dreaming → Portrait/Index；后台跨对话合成、时间改写、可检查、可编辑、可遗忘、可迁移。
3. **透明**：模型、上下文、工具、token、缓存、成本都可见；不静默降级。

## 3. 用户与场景

### 3.1 主用户

- 九年级学生，2027 年中考。
- 第一学期 + 寒假全日制家庭自主学习。
- 9 科 + 体育，平均每科 500 轮/月。
- 同时有编程、接项目、比赛战术、日常判断等需求。
- 预算约 200 元/月；对成本、隐私、性能敏感。

### 3.2 次用户

- ChatGPT Plus 流失用户：想要可迁移、可检查的记忆。
- 学生/自学者：想要 AI 陪着读教材、可视化教学。
- 独立开发者/创业者：想要项目记忆、决策日志、复盘。
- 开源贡献者：想要可自托管、可扩展的记忆内核。

### 3.3 核心场景

| ID | 场景 | 用户要完成的事 |
|---|---|---|
| SC-01 | 学习 | 读教材、听懂概念、做题、批改、复习；跨 9+1 科 |
| SC-02 | 工作 | 在同一对话里跑 Python、处理文件、做 PPT/表格/文档、查资料 |
| SC-03 | 编程 | 读仓库、做安全补丁、看 diff、跑测试、用 git、调试网页 |
| SC-04 | 项目/决策 | 接项目、报价、面试、谈判、记录决策、到期复盘 |
| SC-05 | 日常 | 快速提问、回消息、判断可行性、看新闻/比赛信息 |
| SC-06 | 上下文续接 | 隔天/隔月继续同一件事，不导出/导入、不手动贴状态 |
| SC-07 | 跨域联想 | “这件事让我想起……”：学习 ↔ 编程 ↔ 决策 ↔ 生活 |
| SC-08 | 长期成长 | 几年后回看“当时的我”，看到变化而不是被旧标签定义 |

### 3.4 非目标用户

- 企业团队、多租户、权限管理。
- 需要公开社交/分享记忆的用户。
- 需要手机端优先的用户（后期）。

## 4. 需求原则

| ID | 原则 | 说明 |
|---|---|---|
| R-01 | 叙事优先 | 模型读 Scene/Portrait，不读 JSON 字段；结构只做索引。 |
| R-02 | 原话是真相 | 任何记忆可回溯到原文；摘要不是真相。 |
| R-03 | 成长型记忆 | 区分“过去的我/现在的我”；旧错误不永久定义用户。 |
| R-04 | 模式是假设 | 不贴标签；带证据、反证、不确定性；用户可确认/否定。 |
| R-05 | 一个对话 | 不切模式、不新开对话、不靠摘要交接。 |
| R-06 | 透明 | 每次请求的上下文、工具、token、缓存、成本可见。 |
| R-07 | 本地优先 | 数据在本地；可导出、可删除、可离线阅读。 |
| R-08 | 可遗忘 | 删除是一等公民；级联清理派生数据。 |
| R-09 | 选择性记忆 | “全场景”不等于“全量记录”；朋友记得的是有意义的场景。 |
| R-10 | 证据式完成 | 没有测试/diff/截图/文件证据，不许说“完成”。 |
| R-11 | 情绪安全 | 不在错误后嘲讽、不居高临下、不敷衍。 |
| R-12 | 不静默降级 | 模型/版本/路由变化必须可见。 |

## 5. 功能需求

> 优先级：P0 原型/MVP 必须有；P1 首版后尽快；P2 以后。
> 每条需求写“系统应……”，验收标准写“用户能……”。

### 5.1 对话（CONV）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| CONV-01 | 系统应支持自然语言流式对话，可随时打断/停止 | P0 | 首 token 在可接受时间内出现；可中断 |
| CONV-02 | 系统应允许同一对话里混合学习、工作、编程、决策任务 | P0 | 不需要切换模式/新开对话 |
| CONV-03 | 系统应显示当前使用的模型/档位/工具 | P0 | 每条回复可见 |
| CONV-04 | 系统应支持重试、编辑重发、分支 | P1 | 不破坏已有记忆 |
| CONV-05 | 系统应支持语音输入/朗读 | P2 | 中文可用 |
| CONV-06 | 系统应支持文件/图片/截图作为输入 | P1 | 可在对话中引用 |

### 5.2 记忆（MEM）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| MEM-01 | 系统应保存 Scene：原话、时间、参与者、情境 | P0 | 任意记忆可回溯到至少一条原话 |
| MEM-02 | 系统应生成可读的 Portrait（人物志），不是只存字段 | P0 | 用户可阅读，看到引文、矛盾、变化 |
| MEM-03 | 系统应维护 Index：人物、主题、项目、决策、资源、时间 | P0 | 检索/视图可用；不直接进 Prompt |
| MEM-04 | 系统应自动记录学习状态、误解、待复测 | P0 | 用户不需要手动贴 StudyOS |
| MEM-05 | 系统应支持用户检查/编辑/合并/拆分/遗忘记忆 | P0 | 每一步可见、可撤销 |
| MEM-06 | 遗忘应级联清理派生摘要/人物志/索引/链接 | P0 | 删除后不可检索、不可推断 |
| MEM-07 | 记忆应区分用户原话/助手推断/系统摘要 | P0 | 来源可见；推断可被否定 |
| MEM-08 | 记忆应支持时间有效性（当时为真/现在为真） | P0 | 能看到“过去的我/现在的我” |
| MEM-09 | 系统应支持导入历史对话/资料，构建过去记忆 | P1 | ChatGPT/Claude/Markdown/PDF 可导入 |
| MEM-10 | 系统应支持记忆收件箱：低置信候选待确认 | P1 | 可批量接受/拒绝 |
| MEM-11 | 系统应支持敏感级别与 off-the-record | P1 | 该对话不抽取/不持久化 |
| MEM-12 | 系统应检测重复/矛盾/过期/无证据记忆 | P2 | 给出健康报告，不自动改 |
| MEM-13 | 系统应在后台跨对话 Dreaming，合成人物/偏好/目标/误解/决策 | P0 | 3 次相关对话后，第 4 次不用重复；能回答“我最近在做什么” |
| MEM-14 | 系统应做时间有效性改写（“准备去”→“去过”；旧事实失效） | P0 | 过时信息不再出现；能看到过去的我/现在的我 |
| MEM-15 | 系统应提供 Memory Summary：查看/编辑/删除/按主题控制 | P0 | 用户能改/删；AI 不静默改写 |
| MEM-16 | Dreaming 应可逆：原话不可变，Portrait 版本化，可回滚 | P0 | 每次 consolidation 产生新版本；可回到旧版 |
| MEM-17 | Dreaming 应从 Scene 重新合成，不从上一版 Portrait 生成 | P0 | 来源可追溯；避免自我污染 |
| MEM-18 | 相关记忆应自然注入；不相关不硬塞 | P0 | 相关时出现；无关注入可忽略 |

## 9. 成功标准

### 9.1 3–4 天原型

- 导入 3 份真实对话（物理/数学/接项目），生成对话/场景。
- 同一场景里继续聊，自动带上项目简报、相关场景、人物、决策、薄弱点。
- 不需要导出/导入 JSON，不需要手动贴 StudyOS。
- 记忆检查器可见：它记住了什么、为什么、来源。
- 成本/缓存/上下文可见。
- 学习不被耽误（能实际用来学物理/数学）。
- Dreaming 跑通：问“我物理卡在哪 / 乔瑞丰是谁 / 我最近在做什么”，不用提醒能答；每条能回到原话。
- Memory Summary 可见/可改/可删；删除后检索不到。

### 9.2 5 天 MVP

- 学习 + 项目/决策 + 上下文续接三个演示。
- 一个对话里完成“讲概念 → 做图 → 记录 → 复盘”。
- README/演示/架构图/构建日志。
- 可开源发布。

### 9.3 30 天

- Star 目标（待定）。
- 早期用户留存。
- 记忆质量：用户反馈“记得对”的比例。
- 成本 ≤200 元/月。
- 无静默降级；canary 无显著漂移。

## 12. 附录：需求证据

### 12.1 真实对话样本

| 对话 | 消息/提问 | 时间 | 内容 | 关键证据 |
|---|---:|---|---|---|
| 物理 | 587 / 294 | 9/5–9/22 | 内能、电学、电压 | 20 个 StudyOS；反复“电到底是什么”；“听君一席话” |
| 数学旧 | 429 / 215 | 9/8–10/1 | 一元二次、二次函数、圆 | 13 个 StudyOS；App Block/dynamic-math-tutor 失效 |
| 比较吉林北京题型 | 361 / 182 | 8/25–9/4 | 吉林/北京中考题型、评分 | 22 个 StudyOS；最后转功能设计文档 |
| 接项目建议 | 465 / 235 | 9/17–9/20 | 需求沟通、报价、面试 | 客户、人物、决策、合同 |
| 查阅上下文 | 133 / 67 | 9/20–9/21 | 手动导入 465 条上下文 | ChatGPT 没有项目记忆的直接证据 |

### 12.2 关键观察

- 用户提问极短：物理 294 条里 197 条 <20 字。
- 助手回答偏长：物理平均 862 字，最长 5859 字；数学平均 691 字。
- 失败模式：用户说“不是/听不懂/重新讲/听君一席话”时，助手往往在同一抽象层级继续加词，而不是换讲法/停下来问。
- 用户手动维护 StudyOS：物理 20 次、数学 13 次、题型比较 22 次；这是产品要自动化的核心。
- 用户手动导出/导入上下文：查阅上下文对话上传了 465 条的前一份 JSON；这是产品要消除的痛点。
- 用户需要交互式卡片：数学对话里 `dynamic-math-tutor` 失效，用户明确要 GeoGebra 式可操作组件。
- 情绪安全：答错后助手发 😂，用户说“你还笑话我”；产品红线。

### 12.3 术语

| 术语 | 含义 |
|---|---|
| Scene | 一次对话/会议/工作 session；原话与情境的单位 |
| Portrait | 由 Scene 生成的可读人物志；散文，不是 JSON |
| Index | 人物/主题/项目/决策/资源的索引；用于检索与治理 |
| Pattern | 跨场景的行为假设；带证据/反证，可确认/否定 |
| Decision | 决策记录：选项/标准/选择/理由/预期/复盘 |
| Resource | 文件夹/资料/仓库/链接/转录；本地读取 |
| Inbox | 未归类的闲聊/临时提问；可归档/提升 |
| View | 按时间/人物/主题/项目/决策组织对话的视图；不是文件夹 |
